Agent 评测平台化，Managed Agents 与工程型 FDE 增多

本周最强信号不是“更多聊天机器人岗位”，而是企业把 Agent 的运行、评测、回归、沙箱、轨迹归因和业务交付拆成独立工程职责。低年限入口仍少，后端基本功与可复现评测成为共同门槛。

报告 / 检索日 2026-10-0939 条初筛 · 34 条去重近 3 个月优先岗位 + 社区面经统一监控
读数说明：39/34 是本次实际查看并记录的公开候选，不代表全市场职位数。企业官网、可信聚合详情、平台卡片和社区自述分层呈现；“本周搜不到”不等于下架，平台估薪不等于招聘方薪资。

01 / 本期最重要的 7 个变化

  1. 评测从方法变成平台：腾讯、钉钉千问办公、蚂蚁、网商银行、上海 AI 实验室的样本共同要求自动化 Pipeline、LLM-as-a-Judge、任务环境、Harness/沙箱、轨迹归因和持续回归，不是纯人工打分。
  2. Managed Agents 成为独立工程对象：腾讯 WorkBuddy 岗位把 Agent 使用、编排、运行、治理、评测放进同一条产品链，说明企业开始招聘“运行与治理层”工程能力。
  3. 后端基本功仍是筛选底座：去哪儿、携程、阿里云公开面经同时追问业务建模、数据结构、数据库、并发/一致性、系统设计；只背 Agent/RAG 名词不足以通过面试。
  4. 统计背景对技术型评测更有价值：网商银行和蚂蚁样本明确出现置信区间、显著性、偏差、噪声、Golden Dataset、A/B 与评分器校准，这比纯模型训练更贴近“统计 + Python + 工程”的转型路径。
  5. FDE 有新增，但不是无门槛扩张：中科曙光出现明确 AI Agent FDE，字节 FDE 公开监控也有新岗位；共同要求生产代码、Linux/Git/Docker、系统集成、私有化部署及客户现场闭环，且常见 3 年经验和出差。
  6. 公开薪资证据仍弱：本周新增高质量官网职位多数不公开薪资；明确低于 15K 下限的卡片已排除，因此不能得出薪资整体上涨或下降结论。
  7. 学习路线无需结构性调整：继续 W06 Tool Calling/最小 Agent Loop → FastAPI/RAG；但从现在开始所有练习都应保留失败处理、日志、测试和评测数据，为后续项目闭环做准备。

06 / 对学习计划与求职准备的影响

不建议改动 V5.8 的主线和周次结构。当前 W06 的 Tool Schema、参数校验、执行结果回传、直接回答分支、max_steps、终止条件和工具失败处理，正好对应本周 JD 的 Tool Calling、Agent Loop、失败兜底和可评测执行。随后 FastAPI、RAG、pytest、Docker 继续按原计划推进。

  1. 从 W06 起增加轻量评测记录：每次运行保存输入、模型决策、工具参数、工具结果、终止原因、步数、耗时和异常类型。
  2. W07/W08 项目增加最小 Golden Set：先做 20–30 条公开/合成案例，统计任务成功率、工具调用正确率、直接回答误判、超步数和失败恢复。
  3. 后端底座不能延期：FastAPI 参数校验/异常、SQL、Linux/Git、pytest 要达到能解释和现场写的程度；面经证据不支持“只学 Agent、跳过后端”。
  4. 项目叙事优先：业务问题 → 为什么用 Agent/Workflow → 工具与数据 → 权限/异常 → 评测指标 → Bad Case → 版本变化，而不是框架名清单。
  5. 投递顺序不变：AI 应用/Agent/Python 后端主投；技术型评测与 AI 数据 Pipeline 辅投；工程型 FDE 只投开发占比高且能接受出差/交付的岗位。

07 / 方法与限制

时间窗：优先 2026-07-10—2026-10-09；仍可访问且具备比较价值的半年内岗位可保留并标日期。来源：企业官网优先；JDWatch/职先机/WatchJobs 等聚合页用于补充岗位字段并明确标注；BOSS/猎聘动态页只作卡片；社区内容单独分层。薪资：明确月薪下限低于 15K 的正式职位不进正文；官网未披露但方向高度相关者保留。

本期限制：招聘动态页存在字段加载差异；部分岗位只能确认职位与技术关键词，年限、城市或发布日期写未知。小红书和脉脉原帖公开可访问性不足，没有绕过登录、验证码或访问限制。公开页不含姓名、邮箱、现雇主、内部项目、数据或规则。
