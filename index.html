02全部学习教程 / 解读

  • S1-1R
    Python 工程恢复 + LLM API 证据包V6.0 当前执行
    由于尚无 S1-1 验收证据，本期不推进 S1-2；用消息校验、uv/Git 与 pytest 收口可复现工程基础。 完成真实模型调用、usage/request id、故意错误和修复记录，形成可检查的最小证据包。
  • S1-1
    Python / Git / uv / pytest 查漏 + LLM APIS1-1 首版教材
    用 Messages 数据结构、函数、模块、异常和类型注解完成 Python 诊断，并以 uv、pytest、Git 留下可复现工程证据。 完成一次真实模型调用、usage 记录和故意错误实验；没有 Key 或运行证据时明确标记待验收。
  • W13
    API + Test + Logging历史教材
    用 Pydantic Schema、依赖注入和稳定错误映射，把现有 RAG Pipeline 封装为边界清晰的 FastAPI 服务。通过 TestClient、dependency override、request_id 日志和 .env 配置，留下正常与异常路径均可复跑的服务证据。
  • W12
    RAG Evaluation历史教材
    建立含 Query、相关 Chunk、参考事实与类别的 Golden Set，分层计算检索命中、召回、排序和回答质量。批量复跑 baseline / rerank，记录延迟、Token 与估算成本，形成带失败分类和工程结论的 baseline 报告。
  • W11
    Retrieval 优化与 Rerank历史教材
    建立 Retrieve → Rerank 两阶段检索，用 Cross-Encoder 对候选 Chunk 重新评分，同时保留原始向量分数。冻结固定测试集，以 Hit@k、MRR、延迟和失败分类比较 baseline 与改进版，只有证据支持时才保留优化。
  • W10
    Vector DB / PostgreSQL 工程化历史教材
    用 PostgreSQL + pgvector 持久化 Chunk、向量、模型版本和 metadata，建立可重复写入的数据契约。完成参数化 Upsert、metadata filter、cosine Top-k 查询，并用基础索引与 EXPLAIN 观察查询路径。
  • W09
    Embedding + Retriever Baseline历史教材
    理解 Embedding 与 cosine similarity，用同一模型为 Chunk 和 Query 生成向量，独立实现稳定 Top-k Retriever。建立固定查询与预期命中文档，对比 k 值并记录失败案例，留下可复测的检索基线。
  • W08
    Document Pipeline + Chunk历史教材
    用纯 Python 读取 TXT / Markdown，完成保守清洗与 metadata 设计，建立可重复运行的 Document Pipeline。实现固定窗口与段落优先两种 Chunk 策略，对比 chunk size / overlap，并用校验与测试留下工程证据。
  • W07
    FastAPI + RAG 全景历史教材
    把已有 LLM / Agent Demo 封装为 FastAPI 服务，明确请求、响应、状态码、异常与测试。完成最小 Embedding / 相似度实验并画清 RAG 全流程，用证据自查进入工程阶段前的 Gate 1。
  • W06
    Tool Calling + Agent Loop历史教材
    以 Hello-Agents 为主教材，学习工具定义、参数校验、结果回传与最小 Agent 循环。交付两个工具及验证脚本，覆盖正常调用、直接回答、参数错误、工具失败和步数上限。
  • W05
    Structured Output + Context + Agent 全景历史教材
    用 JSON Schema、Pydantic 与 Structured Output 建立可校验的程序接口。交付双版本 Demo、失败校验与 Context 对照，画清 Prompt / Workflow / Agent / RAG 边界。
  • W04
    LLM 最小底层与模型行为历史归档
    建立 Token → Embedding → Attention / Transformer → Sampling 的生成直觉。交付最小 API Demo、参数与 Token 实验，观察 Streaming / Error，并闭卷重写。
  • W03
    基础启动收尾 + 转入 LLM 主线历史重建
    把运行、修改、Debug、提交和解释串成一个 Python + Git 小闭环。交付综合练习与按需补齐清单；Type Hint、异常、uv 等在真正阻塞时再补。
  • W02
    Python 数据结构 + Git 基础工作流历史重建
    围绕 list / dict / 嵌套结构练过滤、统计、排序，并按函数组织逻辑。交付数据处理练习，用 status → diff → add → commit → log 记录完整开发变化。
  • W01
    Python 基线 + Git 初始化历史重建
    确认变量、类型、条件、循环、函数与模块达到最低可用水平。交付可运行的 Python 小练习和 Git 仓库，独立完成一次修改、检查与提交。
