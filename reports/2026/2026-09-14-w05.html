1. JSON Schema：把字段约定写清楚

P0L22h

用途：自然语言说“返回标题和分数”并没有约束字段是否存在、类型是否正确。Schema 是程序和模型都能引用的输出契约。

具体动作：手写一个与公开模拟文本相关的抽取对象：title 为 string，confidence 为 number，tags 为 string 数组；标明 required 和是否允许额外字段。分别测试合法、漏字段、错类型、额外字段四种输入。

验收：闭卷解释 properties、type、required 的作用，指出“有效 JSON”不等于“符合 Schema”。

这项任务怎么学

对应资料：JSON Schema：Object（properties / required / additionalProperties）；Type-specific Keywords

主导学习方法：AI 主讲 + 实验：让 AI 用中文解释三个关键词，自己先写 Schema 与反例，再用规范原文核对。

建议时长：2h。对象 / 类型 / required 阅读 0.6h；手写 Schema 与 4 组测试输入 1.4h。

学习建议：只学本例需要的 object / string / number / array / required；本周不查全部 JSON Schema 关键字。

2. Pydantic：BaseModel、字段约束与错误

P0L2（项目阶段升 L3）3h

用途：即使模型输出形式受约束，程序入口仍需要一道明确的类型和业务边界检查；ValidationError 是可观察、可处理的失败信号。

具体动作：用 BaseModel 定义同一个抽取对象，给 confidence 加 0–1 约束；调用 model_validate 验证正常数据；主动制造漏字段、错误类型或越界，捕获 ValidationError 并记录 errors()，而不是只在屏幕上看到 traceback。

验收：能独立写一个 BaseModel，解释缺省与必填字段，定位至少两类失败并说出下一步应修正数据还是 Schema。

这项任务怎么学

对应资料：Pydantic Models：Basic model usage / Error handling；Fields：约束；Validation Errors：常见错误类型

主导学习方法：官方文档主讲 + 实验：先照最小示例验证一条，再关闭文档独立写字段约束与两个反例；AI 只给 Debug 提示。

建议时长：3h。Models / Fields / Error handling 必要段落 1h；模型、成功 / 失败校验和 Debug 2h。

学习建议：使用当前安装版 Pydantic 的文档；注意默认可能发生类型转换，严格类型仅在真实需要时再补。不要进入复杂 validator 配置课。

3. Structured Output：可消费的模型结果

P0L2–L34h

用途：自由文本依赖正则或临时解析，字段漂移容易让下游程序失败；受约束输出降低格式不确定性，但不能保证字段内容的事实正确。

具体动作：同一公开模拟输入做自由文本与 Structured Output 两版 Demo；检查当前供应商是否支持严格 Schema 或 SDK 解析辅助，使用该接口规定的字段。准备 3 条固定样本，比较解析成功率、字段缺失和下游校验；模拟缺字段数据、拒答或截断等失败路径，明确异常处理。

验收：输出可被 Pydantic 校验的对象，能区分 JSON 语法有效、Schema 符合、语义正确三个层次；能解释失败时记录错误并修正或重试的边界。

这项任务怎么学

对应资料：OpenAI Structured Outputs：使用方式 / 支持的 Schema / 错误与拒答（仅使用 OpenAI 时）；Pydantic Models：model_validate

主导学习方法：官方文档主讲 + 实验主导：先核对实际模型 / SDK 支持范围，自己跑最小版本；AI 协助设计固定样本与 Review 异常处理，不替代首次实现。

建议时长：4h。当前供应商 Structured Output 说明 0.9h；两种调用与失败路径 2.4h；固定样本对照记录 0.7h。

学习建议：只用已选模型 / 供应商；API 字段和模式随版本变化，不直接套用另一接口的 response_format。无可用 API 时先完成本地 Schema / Pydantic 与 mock 输出验证，并如实标注真实调用待完成。

4. Context Engineering：选择而非堆满

P0L22h

用途：Schema 决定输出形式，Context 决定模型能看到的任务材料；无关历史会占预算并干扰结果，过少上下文则丢关键约束。

具体动作：固定同一抽取任务，准备“必要约束”“必要约束 + 干扰文本”“遗漏关键约束”三个消息版本；记录返回字段与误差。写一条自己的上下文选择规则：保留任务目标、输出契约和必要证据，删除重复 / 无关内容。

验收：能解释模型当前看到了哪些消息、何时截断 / 选择上下文，以及 Structured Output 不能替代 Context 设计。

这项任务怎么学

对应资料：OpenAI Conversation state：消息与上下文（若用 OpenAI）；Prompt engineering：约束与示例

主导学习方法：AI 主讲 + 实验：先让 AI 画请求上下文结构，再自己固定输入做三组对照并解释差异。

建议时长：2h。消息与上下文资料 0.7h；三种上下文对照 1h；记录结论 0.3h。

学习建议：仅研究单次请求及简短历史；长期 Memory 与复杂检索留到后续周。

5. Agent 全景：区分 Prompt、Workflow、Agent、RAG

P0L1–L22h

用途：下周要手写 Tool Calling 和 Agent Loop；先明确哪类任务只是单次调用、哪类需要固定步骤或动态工具决策，避免把所有链条称为 Agent。

具体动作：画一张四栏图：Prompt=单次输入设计；Workflow=预先写好的步骤；Agent=模型依据状态选择动作并循环；RAG=检索并注入证据，可嵌入前述形式。给四个小任务贴标签并说明判断依据。

验收：能在 3 分钟内解释四者区别、Agent 的目标 / 状态 / 工具 / 观察 / 终止条件，并指出 RAG 不等于 Agent。

这项任务怎么学

对应资料：Hello-Agents 第一章：智能体定义、类型与范式

主导学习方法：原课程主讲 + AI 重讲：只读第一章与目标直接相关的段落，AI 给反例提问；你独立画图和分类。

建议时长：2h。Hello-Agents 第一章选读 / AI 讲解 0.8h；画图与 4 个案例判断 1.2h。

学习建议：跳过发展史、低代码平台和多 Agent 框架；本周只画架构图，下周才实现 Loop。

6. Optional / Union、嵌套 Model、Context 截断

P1L1；有余力做 L20.5h

用途：这些是 Schema 和上下文的常见扩展，但不是本周主线最小闭环的前置条件。

具体动作：P0 通过后任选一种：给对象加可选字段，或做一层嵌套模型，或写出截断优先级；不要三项都开课。

验收：能解释所选扩展解决的真实问题，不改变原有 P0 Demo 的可运行性。

这项任务怎么学

对应资料：Pydantic Models：Nested models；Fields：默认值；Conversation state：上下文管理（条件参考）

主导学习方法：JIT 实验：先遇到确实需要的场景才查文档，AI 帮缩小阅读范围。

建议时长：0.5h。任选一项概念 / 示例 0.25h；尝试改动现有 Demo 0.25h。

学习建议：P0 受阻时直接把这 0.5h 转为 Debug；P2 内容全部取消。

概念连接：Context 选择模型输入 → Structured Output 约束输出形式 → Pydantic 校验程序边界 → Workflow / Agent 决定是否继续执行动作。RAG 是提供外部证据的一种方法，不自动等于 Agent。
