3. 每个任务的详细解读

任务 1 · Python / Git 综合小闭环任务 2 · Debug 与解释任务 3 · JIT 补齐入口

1. Python / Git 综合小闭环

P0L2

理解与用途：这一任务检查你能否把已经学过的语法组合成可运行程序；通过后就具备继续学习 LLM API 的最低基础。

具体怎么做：沿用已有练习或建一个小脚本，输入合成记录，用函数清理和统计，再输出结果。运行后改一个过滤条件，核对结果并记录 Git 变更。

学到这里即可：独立走完输入、处理、输出和提交，关闭答案后重写核心函数。

这项任务怎么学

学习参考资料：Python 数据结构；函数；Pro Git 简体中文版，第 2 章 Git 基础。只查忘记的点。

学习方法：实验 / 项目主导：先独立完成输入、处理、输出；只在卡住时向 AI 请求逐级提示，完成后做小范围 Review 并提交。

建议时长：8h。综合实现 6h + Git 提交与变更回看 2h。

学习建议：沿用合成记录或旧练习；不扩大成带数据库、网页或框架的新系统。这里的 Git 时间已经计入 8h。

2. Debug 与解释

P0L2

理解与用途：错误堆栈（traceback）指出程序在哪条调用链上失败；找到自己的代码位置和出错输入，比直接复制修复代码更有价值。

具体怎么做：故意访问一个缺失字段或传入错误类型。先读最后的错误类型和信息，再定位自己的代码行，打印相关输入；修复后重跑正常与异常样例。

学到这里即可：能说清错误类型、位置、原因、修复方式；不以宽泛捕获把错误隐藏。

这项任务怎么学

学习参考资料：Python Tutorial：错误与异常：错误信息、异常与处理示例。

学习方法：实验主导：先制造一个可控错误，自行读 traceback；写出原因假设再修改，正常路径和原失败输入都重新运行。

建议时长：3h。读错与定位 0.5h + 制造错误、修复及边界复跑 2.5h。

学习建议：先定位错误再问 AI；请求“提示下一步该看哪里”，避免直接复制完整修复。

3. JIT 补齐入口

P1L1

理解与用途：按需补齐（Just-in-Time，JIT）意味着能力真正阻塞当前产出时再学，不把所有未来工程能力当成旧欠账。

具体怎么做：列出 Type Hint、异常、OOP、uv、pyproject.toml、项目结构和 pytest 的用途及触发条件。例如依赖无法安装时查环境管理，函数边界无法验证时补最小测试。

学到这里即可：每项能写一句“何时用、补到哪一步”；无需本周逐项实现。

这项任务怎么学

学习参考资料：Python typing；uv Getting Started；Master Plan 的 W01–W03 JIT 清单。仅作为按需入口。

学习方法：AI 主讲：每项只问用途、触发条件和最小补齐动作；自己写成清单，确认进入 W04 的最小运行环境。

建议时长：2h。用途梳理 0.5h + 触发式清单及 W04 准备 1.5h。

学习建议：不要求现在逐项实现 Type Hint、OOP、uv、pytest。P0 超时可挪用本时段，保留简短触发清单即可。

知识之间的关系

Python 基础+Git 基础→可运行小闭环→JIT 清单→W04 LLM / API

这周真正解决的是“何时停止补基础”。只要能独立运行、修改、Debug 和 commit，就不再等待所有工程知识学完。
