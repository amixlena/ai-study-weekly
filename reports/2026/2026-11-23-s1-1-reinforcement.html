1｜先看懂 Messages 的真实数据形态

正常档 1h

消息（message）不是一段随意拼接的字符串，而是带角色与内容的结构化数据。下面的 messages 是一个 list；list 中有两个元素，每个元素都是 dict；role 和 content 是 key，对应字符串是 value。循环中的 message 每次指向其中一个字典。

messages: list[dict[str, str]] = [
    {"role": "system", "content": "用两句中文回答。"},
    {"role": "user", "content": "为什么要记录 token usage？"},

for message in messages:
    role = message["role"]
    content = message["content"]
    print(role, content)

list[dict[str, str]] 是类型注解：外层预期是 list，元素预期是 key/value 均为字符串的 dict。它帮助阅读和静态检查，但不会在运行时自动拒绝错误数据，所以输入边界仍需要显式校验。

2｜函数、模块与异常边界

正常档 1.5h

函数（function）把输入、处理、输出封装成可重复调用的单元；模块（module）通常是一个可导入的 .py 文件；异常（exception）让非法输入显式失败。S1-1 的重点是：调用 API 之前先把本地数据校验清楚，避免服务端报错掩盖本地问题。

# src/llm_api_demo/messages.py
ALLOWED_ROLES = {"system", "user", "assistant"}

def normalize_messages(
    raw_messages: list[dict[str, str]],
) -> list[dict[str, str]]:
    if not raw_messages:
        raise ValueError("messages must not be empty")

    normalized: list[dict[str, str]] = []
    for index, message in enumerate(raw_messages):
        role = message.get("role", "")
        content = message.get("content", "").strip()
        if role not in ALLOWED_ROLES:
            raise ValueError(f"invalid role at index {index}: {role!r}")
        if not content:
            raise ValueError(f"empty content at index {index}")
        normalized.append({"role": role, "content": content})
    return normalized

raw_messages 是原始输入；normalized 是新 list，避免修改调用者的数据；enumerate 同时产生索引和当前字典；.get() 在 key 缺失时给默认值；.strip() 去掉首尾空白；raise ValueError 终止当前函数并把明确原因交给调用者。

错误为什么错正确方向
except Exception: pass吞掉 traceback，程序继续使用未知状态只捕获当前层能处理的异常；其余继续抛出
非法输入返回空 list调用者无法区分“合法空结果”和“校验失败”对非法输入抛明确异常
模块导入时立即请求 API导入就产生外部副作用，测试困难把调用放进函数与 main()

4｜pytest：正常路径和失败路径都要成为证据

正常档 1.5h

测试（test）把预期行为写成可重复执行的检查。assert比较实际结果与预期结果；pytest.raises确认某段代码应该抛出指定异常。测试失败不是“没学会”的判决，而是定位输入、实际输出和假设差异的工具。

# tests/test_messages.py
import pytest
from llm_api_demo.messages import normalize_messages

def test_strips_content_without_mutating_input():
    raw = [{"role": "user", "content": "  hello  "}]
    assert normalize_messages(raw) == [
        {"role": "user", "content": "hello"}
    ]
    assert raw[0]["content"] == "  hello  "

def test_rejects_empty_list():
    with pytest.raises(ValueError, match="must not be empty"):
        normalize_messages([])

def test_rejects_invalid_role():
    raw = [{"role": "admin", "content": "hello"}]
    with pytest.raises(ValueError, match="invalid role"):
        normalize_messages(raw)

5｜真实 LLM API：输入、输出、usage 与 request id

正常档 2.25h

模型 API（Model API）是 Python 程序与模型服务之间的接口。程序负责构造输入、发送请求、保存可观测信息并处理异常；模型只生成响应。示例使用当前 OpenAI Responses API；模型名从环境变量读取，必须以账户实际可用模型为准。

# src/llm_api_demo/llm_api.py
import os
from openai import OpenAI
from llm_api_demo.messages import normalize_messages

def create_demo_response(prompt: str):
    model = os.environ["OPENAI_MODEL"]
    messages = normalize_messages([
        {"role": "system", "content": "用两句中文回答；不确定就说不确定。"},
        {"role": "user", "content": prompt},
    ])
    client = OpenAI()
    return client.responses.create(model=model, input=messages)

def main() -> None:
    response = create_demo_response("为什么要记录 token usage？")
    print(response.output_text)
    print({
        "input_tokens": response.usage.input_tokens,
        "output_tokens": response.usage.output_tokens,
        "total_tokens": response.usage.total_tokens,
        "request_id": response._request_id,
    })

if __name__ == "__main__":
    main()

os.environ["OPENAI_MODEL"]读取必须存在的变量；缺失会抛 KeyError。OpenAI()默认从环境读取 API Key。input=messages传入角色化消息；output_text是聚合后的文本；usage记录输入、输出和总 Token；成功响应的 _request_id用于排查一次具体请求。不要在代码、日志、截图或 HTML 中输出 Key。

6｜错误实验：错误类别决定处理方式

正常档 0.75h

连接失败、超时、认证失败、限流和服务端错误不是同一种问题。SDK 连接失败会抛 APIConnectionError；超时抛 APITimeoutError；4xx/5xx 是 APIStatusError 的子类。失败请求的 request id 从异常对象的 request_id 读取。

import openai

try:
    response = create_demo_response("解释 system message 的作用。")
except openai.AuthenticationError as exc:
    print("认证失败：检查 Key，但不要打印 Key。", exc.request_id)
except openai.RateLimitError as exc:
    print("限流：记录 request_id，按服务提示等待。", exc.request_id)
except openai.APITimeoutError:
    print("超时：记录发生阶段，再决定是否重试。")
except openai.APIConnectionError as exc:
    print("连接失败：检查网络、代理或证书。", exc.__cause__)
except openai.APIStatusError as exc:
    print("非成功状态：", exc.status_code, exc.request_id)
else:
    print(response.output_text)

故意错误：把 OPENAI_MODEL 临时设为明显不存在的值，运行一次并记录异常类型、状态码、request id、原因和修复；随后恢复正确模型并重跑。不要故意把真实 Key 写入文件制造认证错误。SDK 对部分连接错误、408、409、429 和 5xx 默认会重试，因此实验记录要注明“最终看到的错误”，不要把自动重试次数误写成自己的代码逻辑。
