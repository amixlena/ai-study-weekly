二、Retrieve → Rerank：先多召回，再精排序

2 小时
P0AI 主讲 + 官方资料

First-stage Retrieval（第一阶段召回）用向量索引快速取较大的候选集；Reranking（重排序）让模型同时读取 Query 和每个候选 Chunk，输出相关性分数，再截取 final_k。Cross-Encoder 通常更精细但更慢，所以只处理候选，不扫描全库。

Query→Vector Top-20→Cross-Encoder→Final Top-3
@dataclass(frozen=True)
class SearchHit:
    chunk_id: str
    content: str
    vector_score: float
    rerank_score: float | None = None

def retrieve_then_rerank(query: str, candidate_k: int = 20, final_k: int = 3):
    if not 1 <= final_k <= candidate_k:
        raise ValueError("必须满足 1 <= final_k <= candidate_k")
    candidates = vector_store.search(query, top_k=candidate_k)
    return reranker.rerank(query, candidates, top_k=final_k)

关键边界：如果正确 Chunk 不在 candidate_k 中，Reranker 无法创造它；先增大候选或修复召回。如果正确 Chunk 已在候选中但排得靠后，才是 Reranker 的主要用武之地。

练习

从一条 baseline 失败查询开始，分别记录正确 Chunk 是否出现在 Top-3、Top-10、Top-20。把问题标成“未召回”或“已召回但排序低”，不要立即改模型。

三、Cross-Encoder：让 Query 与 Chunk 联合评分

3.5 小时
P0官方文档主讲 + 实验主导

Cross-Encoder（交叉编码器）接收成对文本 (query, document)，联合编码后输出相关性分数。它不生成可预存的 Chunk 向量，因此更适合第二阶段精排。中文 / 多语言示例选用上游模型卡明确提供 CrossEncoder 用法的 BAAI/bge-reranker-v2-m3；首次下载较大，若本机资源不足，保留接口并换成已授权的轻量或托管 Rerank 服务。

from sentence_transformers import CrossEncoder

class LocalCrossEncoderReranker:
    def __init__(self, model_name: str = "BAAI/bge-reranker-v2-m3"):
        self.model = CrossEncoder(model_name)

    def rerank(
        self,
        query: str,
        candidates: list[SearchHit],
        top_k: int,
    ) -> list[SearchHit]:
        if not query.strip():
            raise ValueError("query 不能为空")
        if not candidates:
            return []
        pairs = [(query, hit.content) for hit in candidates]
        scores = self.model.predict(pairs)
        rescored = [
            SearchHit(
                chunk_id=hit.chunk_id,
                content=hit.content,
                vector_score=hit.vector_score,
                rerank_score=float(score),
            )
            for hit, score in zip(candidates, scores, strict=True)
        ]
        rescored.sort(
            key=lambda hit: (-(hit.rerank_score or float("-inf")), hit.chunk_id)
        )
        return rescored[:top_k]

错误示例 → 原因 → 正确写法

错误：对全库逐条精排

pairs = [(query, row.content) for row in all_chunks]

延迟与成本随全库增长。先用 Vector Store 召回 candidate_k。

错误：把不同模型分数直接混加

score = vector_score + rerank_score

两种分数尺度未校准。最小版本直接按 rerank_score 排，并保留原分数用于诊断。

模型与设备：第一次加载会下载权重；不要把模型文件提交 Git。MPS / CPU 是否可用、批量大小和最大长度由实际模型及设备决定。本周只测小候选集，不为速度盲目改精度或量化。

时间拆分

官方概念 35m → 环境与单对评分 45m → 候选批量评分 60m → 排序与稳定 tie-break 35m → 空候选 / 超长文本 / 模型失败 35m。先用 3 条候选跑通，再扩到 candidate_k=10/20。

四、可比较实验：Hit@k、MRR、延迟与逐条差异

3 小时
P0Evaluation 预埋

Hit@k回答“前 k 个里是否至少有一个正确 Chunk”；MRR（Mean Reciprocal Rank，平均倒数排名）奖励正确结果排得更靠前。W12 才系统学习 Evaluation，本周只用两个透明指标支持检索决策。

def first_relevant_rank(ids: list[str], expected: frozenset[str]):
    return next((i for i, item in enumerate(ids, start=1) if item in expected), None)

def metrics(result_ids: list[str], expected: frozenset[str], k: int) -> dict:
    rank = first_relevant_rank(result_ids[:k], expected)
    return {
        f"hit@{k}": int(rank is not None),
        "reciprocal_rank": 0.0 if rank is None else 1.0 / rank,
    }
from time import perf_counter

def run_case(case: RetrievalCase, use_rerank: bool) -> dict:
    start = perf_counter()
    hits = (
        retrieve_then_rerank(case.query, candidate_k=20, final_k=3)
        if use_rerank else vector_store.search(case.query, top_k=3)
    )
    elapsed_ms = (perf_counter() - start) * 1000
    ids = [hit.chunk_id for hit in hits]
    return {"case_id": case.case_id, "ids": ids, "latency_ms": elapsed_ms,
            **metrics(ids, case.expected_ids, k=3)}

六、条件补充：关键词检索与 RRF

1 小时
条件 P0 / P1仅词法失败明显时

若专有名词、编号、函数名等被向量检索漏掉，可用 PostgreSQL Full Text Search 建一个词法结果集，再用 RRF（Reciprocal Rank Fusion，倒数排名融合）合并排名。注意 PostgreSQL ts_rank / ts_rank_cd 是全文检索排名函数，不要把它错误称为 BM25。

def reciprocal_rank_fusion(result_lists: list[list[str]], rank_constant: int = 60):
    scores: dict[str, float] = {}
    for ids in result_lists:
        for rank, chunk_id in enumerate(ids, start=1):
            scores[chunk_id] = scores.get(chunk_id, 0.0) + 1.0 / (rank_constant + rank)
    return sorted(scores, key=lambda item: (-scores[item], item))
SELECT chunk_id, ts_rank_cd(
    to_tsvector('simple', content),
    plainto_tsquery('simple', %s)
) AS lexical_score
FROM document_chunks
WHERE to_tsvector('simple', content) @@ plainto_tsquery('simple', %s)
ORDER BY lexical_score DESC
LIMIT %s;
中文边界：PostgreSQL 内置配置并不等于成熟中文分词方案。本周只用合成的英文 / 标识符 / 已可分词文本验证 RRF 数据流；若中文词法检索需要额外插件，不在本周安装新生态。
