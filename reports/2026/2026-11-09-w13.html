1｜服务边界与 Request / Response Schema

3h

API（Application Programming Interface，应用程序接口）是调用方与 RAG 服务之间的契约。HTTP 层应该稳定，即使内部 Retriever、Reranker 或模型以后替换，客户端也不必跟着重写。

为什么要学：Agent、Web UI、批量评测和其他后端都需要通过明确输入输出调用同一能力。Schema 同时承担文档、校验和回归边界。

最小目录

src/
  api/
    main.py
    schemas.py
    dependencies.py
  rag/
    service.py
tests/
  test_query_api.py
.env.example

最小但完整的 Schema

# src/api/schemas.py
from pydantic import BaseModel, Field

class QueryRequest(BaseModel):
    question: str = Field(min_length=1, max_length=1000)
    top_k: int = Field(default=3, ge=1, le=10)

class SourceItem(BaseModel):
    chunk_id: str
    text_preview: str
    score: float | None = None

class QueryResponse(BaseModel):
    answer: str
    sources: list[SourceItem]
    request_id: str

设计理由：question 限长避免空输入和意外超长请求；top_k 限制资源范围；响应返回来源 ID 便于调试与评测，但只给必要 preview，不暴露整库内容。

错误示例 → 报错 → 正确写法

# 错误：Route 收 dict，再手动猜字段
@app.post("/query")
def query(payload: dict):
    question = payload["question"]  # 可能 KeyError

使用 QueryRequest 后，FastAPI 会在进入业务逻辑前返回结构化 422；不要把输入错误伪装成 500。

练习骨架

@app.post("/query", response_model=QueryResponse)
def query_rag(payload: QueryRequest):
    # TODO：暂时返回固定响应，先确认契约
    ...

先写再问：先自己补一个固定响应；再用 /docs 和 curl 验证。边界：空字符串、1001 字符、top_k=0/11、缺字段、额外字段。完成点：能解释 422 为什么发生。

2｜Dependency Injection 与 RAG Service

2.5h

依赖注入（Dependency Injection）让 Route 声明“需要一个 RAG Service”，而不是在函数里直接连接数据库和创建模型。这样测试可以替换 Service，也避免每个请求重复加载昂贵资源。

# src/rag/service.py
from dataclasses import dataclass
from typing import Protocol

@dataclass(frozen=True)
class RAGResult:
    answer: str
    sources: list[dict]

class RAGService(Protocol):
    def answer(self, question: str, top_k: int) -> RAGResult: ...

# src/api/dependencies.py
def get_rag_service() -> RAGService:
    # 返回应用启动时创建或缓存的真实实现
    return real_rag_service
# src/api/main.py
from typing import Annotated
from fastapi import Depends, FastAPI

app = FastAPI(title="RAG Service")

@app.post("/query", response_model=QueryResponse)
def query_rag(
    payload: QueryRequest,
    service: Annotated[RAGService, Depends(get_rag_service)],
) -> QueryResponse:
    result = service.answer(payload.question, payload.top_k)
    return QueryResponse(
        answer=result.answer,
        sources=[SourceItem(**item) for item in result.sources],
        request_id="temporary",
    )
关于 def / async def：如果当前 PostgreSQL / 模型 SDK 是同步阻塞调用，先用普通 def Route；不要只为“看起来现代”改成 async def 后仍直接执行阻塞代码。本周不做异步重构。

练习骨架

把 W11/W12 的真实 Pipeline 包成一个实现 answer() 的类；Route 中不得出现 SQL、Embedding、Prompt 或供应商 SDK。刻意替换一个 FakeRAGService，确认接口仍可用。

边界测试：空 sources、多个 sources、score 为 null、Service 返回非法字典。非法内部结果应在开发/测试暴露，不要静默补字段。

3｜Exception、Status Code 与安全错误响应

2.5h

状态码（Status Code）告诉调用方结果类别：2xx 成功；4xx 是请求或业务条件不满足；5xx 是服务端或依赖失败。错误响应要稳定，但不能回传 SQL、密钥、内部路径或模型原始异常。

场景状态码理由
Schema 不合法422FastAPI 自动校验，业务函数不应执行
知识库无可用答案404资源/答案不存在，不是系统崩溃
向量库或模型暂时不可用503依赖故障，可稍后重试
未预期异常500对外统一消息，对内记录堆栈
from fastapi import HTTPException

class KnowledgeBaseUnavailable(RuntimeError):
    pass

@app.post("/query", response_model=QueryResponse)
def query_rag(
    payload: QueryRequest,
    service: Annotated[RAGService, Depends(get_rag_service)],
):
    try:
        result = service.answer(payload.question, payload.top_k)
    except KnowledgeBaseUnavailable:
        raise HTTPException(
            status_code=503,
            detail={"code": "DEPENDENCY_UNAVAILABLE",
                    "message": "knowledge service unavailable"},
        )
    if not result.answer:
        raise HTTPException(
            status_code=404,
            detail={"code": "ANSWER_NOT_FOUND",
                    "message": "no answer found"},
        )
    return build_response(result)

常见错误

  • except Exception: return {"error": ...} 仍返回 200，调用方会误判成功。
  • 把 str(exc) 原样返回，可能泄露连接串、SQL 和内部路径。
  • 所有失败都返回 500，导致无法区分是否应修请求、重试或报警。
  • 吞掉异常但不写日志，之后无法定位。

练习骨架

让 Fake Service 分别返回正常、空答案和抛出 KnowledgeBaseUnavailable；记录预期状态码和 JSON。再制造一个未预期 ValueError，观察测试环境的异常行为；对外 500 处理放在统一 handler，避免每个 Route 复制。

4｜TestClient、pytest 与 Dependency Override

3.5h

API 测试验证 HTTP 契约，不需要真的启动端口。FastAPI 的 TestClient 基于 HTTPX，可在普通 pytest def test_... 中调用。

# tests/test_query_api.py
import pytest
from fastapi.testclient import TestClient
from src.api.main import app
from src.api.dependencies import get_rag_service
from src.rag.service import RAGResult

class FakeRAGService:
    def answer(self, question: str, top_k: int) -> RAGResult:
        return RAGResult(
            answer="退款将在 3 到 5 个工作日内原路退回。",
            sources=[{"chunk_id": "refund-1",
                      "text_preview": "退款时效...",
                      "score": 0.91}],
        )

@pytest.fixture
def client():
    app.dependency_overrides[get_rag_service] = lambda: FakeRAGService()
    with TestClient(app) as test_client:
        yield test_client
    app.dependency_overrides = {}

def test_query_success(client: TestClient):
    response = client.post("/query", json={
        "question": "退款多久到账？",
        "top_k": 3,
    })
    assert response.status_code == 200
    body = response.json()
    assert "3 到 5 个工作日" in body["answer"]
    assert body["sources"][0]["chunk_id"] == "refund-1"
    assert body["request_id"]

测试隔离：fixture 结束必须清空 app.dependency_overrides，否则后续测试会被污染。测试运行时不得访问真实向量库、真实模型或付费 API；可另外保留少量显式 integration test，但不属于本周 P0。

Debug 顺序

  1. 先看状态码与 response.text。
  2. 确认 override 的 key 是原依赖函数本身。
  3. 确认 Fake 返回结构满足内部契约。
  4. 单独运行失败测试：pytest -q tests/test_query_api.py -k 503。
  5. 最后才怀疑 FastAPI 或 pytest。

完成点：至少 1 个正常 + 4 个异常/边界测试；重复运行结果稳定，网络断开也能通过。

5｜基础 Logging 与 request_id

2h

日志（Logging）记录运行事件；request_id（请求标识）把一次请求经过的 API、Retriever、模型和错误串起来。日志不是把所有变量都打印出来，而是留下定位所需的最小事实。

import logging
from time import perf_counter
from uuid import uuid4
from fastapi import Request

logger = logging.getLogger(__name__)

@app.middleware("http")
async def request_context(request: Request, call_next):
    request_id = str(uuid4())
    started = perf_counter()
    try:
        response = await call_next(request)
        return response
    except Exception:
        logger.exception("request_failed request_id=%s path=%s",
                         request_id, request.url.path)
        raise
    finally:
        elapsed_ms = (perf_counter() - started) * 1000
        logger.info("request_finished request_id=%s path=%s elapsed_ms=%.1f",
                    request_id, request.url.path, elapsed_ms)

实际 Route 可从 request.state 读取 request_id 并写入响应。为保持示例短小，练习中补上 request.state.request_id = request_id 与响应 Header。

级别与隐私

  • INFO：请求完成、状态码、耗时、top_k、返回来源数量。
  • WARNING：可恢复退化，如 rerank 回退到 baseline。
  • ERROR / exception：请求失败，保留堆栈但对外隐藏内部信息。
  • 不要记录：API Key、Authorization Header、数据库连接串、完整文档、完整 Prompt、公开页面禁止的私人数据。

练习骨架

把 request_id 放入 request.state、响应 JSON 和 X-Request-ID；用 caplog 检查成功请求有 INFO，失败请求有 ERROR。避免断言完整日志字符串，只断言事件名、级别和 request_id 存在。

6｜Settings、.env 与综合闭卷验收

2.5h

配置（Configuration）是环境可变而代码不应硬编码的值，例如数据库地址、模型名、日志级别。pydantic-settings 可以从环境变量和 dotenv 读取并校验类型。

# src/config.py
from functools import lru_cache
from pydantic import Field
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        extra="ignore",
    )
    app_env: str = "dev"
    log_level: str = "INFO"
    database_url: str
    model_name: str
    api_key: str = Field(repr=False)

@lru_cache
def get_settings() -> Settings:
    return Settings()
# .env.example（可以提交）
APP_ENV=dev
LOG_LEVEL=INFO
DATABASE_URL=postgresql://user:password@localhost:5432/rag
MODEL_NAME=replace-me
API_KEY=replace-me

# .gitignore（真实 .env 不提交）
.env
优先级：真实环境变量通常应覆盖 dotenv；.env 是本地便利，不是秘密管理系统。测试通过 dependency override 提供 Settings，不修改开发机真实环境。

常见错误

  • 从任意工作目录运行时找不到相对路径 .env；需要明确运行目录或路径策略。
  • 把真实密钥写进 .env.example、测试快照或日志。
  • 导入模块时立即创建全局客户端，导致测试还没 override 就连外部服务。
  • 配置缺失时静默使用危险默认值；关键连接与密钥应让启动明确失败。

闭卷重写

  1. 关闭页面，写出 Request / Response Model 与 POST /query。
  2. 用依赖注入接入一个 Fake Service，再写成功测试。
  3. 补 422、404、503 三条异常测试。
  4. 解释 request_id 如何经过日志、响应 Header 与 JSON。
  5. 从空目录写 Settings、.env.example 与 .gitignore。

完成点：本地可启动；pytest -q 离线通过；错误不泄露内部异常；日志能定位请求；真实密钥未进入 Git。
