1. list / dict / set / tuple 与嵌套结构

P0L2

理解与用途：list 表示一组有序记录，dict 按字段存值，set 用来去重，tuple 表示通常不修改的组合。后续 Messages 就是 list 中嵌套 dict。

具体怎么做：用 3 条合成消息练习取 role/content、过滤 user、统计角色数量、去重和排序；先写普通循环，理解后再改为推导式。分别测试空列表和缺失字段。

学到这里即可：不看答案完成过滤、统计、排序和结构转换，解释为何选用相应结构。

这项任务怎么学

学习参考资料：Python Tutorial：数据结构：列表、集合、字典、推导式及遍历技巧。

学习方法：AI 主讲 + 实验主导：让 AI 围绕合成 Messages 讲结构；自己完成遍历、过滤、统计和排序，再对照文档改成推导式。

建议时长：9h。AI / 文档 3h + 数据结构练习与 Debug 6h。

学习建议：先写能看懂的普通循环；不要为了代码短强行嵌套推导式。每种转换都保留一组输入与预期输出。

2. 函数与模块组织

P0L2

理解与用途：函数为一段处理逻辑定义输入输出，模块让不同文件复用函数；为 API 与工具函数的拆分做准备。

具体怎么做：把上面的处理拆成过滤、统计、格式化 2–3 个函数，放入练习模块并从入口 import。先运行原版本，再逐项对比拆分后的结果。

学到这里即可：从另一个文件调用函数，解释输入输出及是否修改原始数据。

这项任务怎么学

学习参考资料：定义函数；模块：只读定义、导入和模块使用示例。

学习方法：实验主导：把上一任务已能运行的逻辑分成小函数；先明确参数和返回值，再从入口文件 import，比较拆分前后输出。

建议时长：2h。查文档 0.5h + 拆函数、跨文件调用 1.5h。

学习建议：复用上一任务的数据，不另开新项目；暂不引入复杂类层级或设计模式。

3. Git 日常工作流

P0L2；remote 为 L1

理解与用途：每轮变更都可回看，后续才有条件定位某次 API 或 Agent 行为为何改变。remote 是远程仓库地址，push/pull 用于同步。

具体怎么做：围绕同一练习分小步修改，每步先看 status/diff 再提交。用 log 找一次变更并解释它；已有远程仓库时练习同步，不额外展开复杂分支策略。

学到这里即可：能用 diff/log 复盘变化，并说清本地 commit 与远程同步的区别。

这项任务怎么学

学习参考资料：Pro Git 简体中文版，第 2 章 Git 基础：记录更新、查看历史、远程仓库；GitHub Docs：远程仓库。

学习方法：官方文档 + 实验主导：围绕前两项练习分小步提交；每次先 status/diff，再 add/commit，最后用 log 说明变化。

建议时长：3h。概念 / 文档 0.5h + 小步提交与回看 2.5h。

学习建议：优先熟练本地工作流；远程同步只在已有仓库上练习，不为本周任务额外搭建复杂协作流程。
