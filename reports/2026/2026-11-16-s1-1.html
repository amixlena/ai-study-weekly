1｜list / dict 与 Messages 的真实数据形态

正常档 1.25h

列表（list）保存有顺序的一组元素；字典（dictionary，dict）用 key 找 value。模型的 Messages 可以理解为“外层 list 装多条消息，每条消息是一个 dict”。这不是抽象语法题：Structured Output、Tool Calling、日志和评测数据都反复使用同样的嵌套结构。

messages = [
    {"role": "system", "content": "请用一句中文回答。"},
    {"role": "user", "content": "什么是 token？"},
]

first_message = messages[0]
role = first_message["role"]
content = first_message["content"]

print(role)      # system
print(content)   # 请用一句中文回答。

messages 是外层 list，有两个元素；messages[0] 取第一条消息并赋给 first_message；它是 dict，包含 role 和 content 两个 key。first_message["role"] 读取角色值。key 拼错会抛 KeyError，索引越界会抛 IndexError。

2｜函数、模块、类型注解与异常边界

正常档 1.25h

函数（function）把输入、处理和输出组成可复用单元；模块（module）通常就是一个可导入的 .py 文件；类型注解（type hint）帮助人和工具理解预期类型，但 Python 运行时不会自动替你校验。异常用于让非法输入显式失败，不要静默返回似是而非的数据。

# src/llm_api_demo/messages.py
ALLOWED_ROLES = {"system", "user", "assistant"}

def normalize_messages(
    raw_messages: list[dict[str, str]],
) -> list[dict[str, str]]:
    if not raw_messages:
        raise ValueError("messages must not be empty")

    normalized: list[dict[str, str]] = []
    for index, message in enumerate(raw_messages):
        role = message.get("role", "")
        content = message.get("content", "").strip()
        if role not in ALLOWED_ROLES:
            raise ValueError(f"invalid role at index {index}: {role!r}")
        if not content:
            raise ValueError(f"empty content at index {index}")
        normalized.append({"role": role, "content": content})
    return normalized

raw_messages 是调用者传入的原始 list；normalized 是新 list，避免直接修改输入；enumerate 同时给出索引 index 和当前字典 message；.get() 在 key 缺失时返回默认空字符串；.strip() 去掉首尾空白；raise ValueError 把错误位置交给调用者处理。

错误示例 → 原因 → 正确方向

错误写法或现象原因正确方向
except Exception: pass异常被吞掉，程序继续使用无效状态只捕获能处理的异常；其余保留 traceback
类型注解写了 str 就认为运行时会拒绝 int注解默认不做运行校验在输入边界显式检查；后续再用 Pydantic
模块导入时立即发送 API 请求导入产生外部副作用，测试困难把调用放入函数和 main()

3｜uv 项目与 Git 最小可复现闭环

正常档 1.5h

uv负责项目环境、依赖与锁文件；Git记录代码变化。pyproject.toml声明依赖范围，uv.lock保存解析后的精确版本，两者都应进入版本控制；.venv、真实 .env 和缓存不应提交。

# 初始化并进入项目

# 在项目环境中运行

# 查看并提交明确的文件
git status

4｜pytest：把正常与错误路径写成证据

正常档 1.5h

测试（test）不是证明“代码永远正确”，而是把预期行为变成可重复检查。S1-1 只需要普通测试函数、assert 和 pytest.raises；复杂 fixture、参数化与覆盖率工具不是 P0。

# tests/test_messages.py
import pytest
from llm_api_demo.messages import normalize_messages

def test_normalize_messages_strips_content():
    raw = [{"role": "user", "content": "  hello  "}]
    assert normalize_messages(raw) == [
        {"role": "user", "content": "hello"}
    ]

def test_normalize_messages_rejects_empty_list():
    with pytest.raises(ValueError, match="must not be empty"):
        normalize_messages([])

def test_normalize_messages_rejects_invalid_role():
    raw = [{"role": "admin", "content": "hello"}]
    with pytest.raises(ValueError, match="invalid role"):
        normalize_messages(raw)

# TODO：补 content 只有空格
# TODO：补缺少 role
# TODO：确认函数没有修改 raw

5｜真实 LLM API Messages 调用

正常档 2.5h

模型 API（Model API）是程序与模型服务之间的接口。程序负责读取环境变量、构造 Messages、发送请求、处理返回值与异常；模型只生成响应，不替 Python 执行本地函数。示例使用当前官方 Responses API；可用模型名必须以账户实际可用列表和供应商文档为准，不在教程中硬编码。

# src/llm_api_demo/llm_api.py
import os
from openai import OpenAI
from llm_api_demo.messages import normalize_messages

def create_demo_response(prompt: str):
    model = os.environ["OPENAI_MODEL"]
    messages = normalize_messages([
        {"role": "system", "content": "用两句中文回答；不确定就明确说不确定。"},
        {"role": "user", "content": prompt},
    ])
    client = OpenAI()
    return client.responses.create(model=model, input=messages)

def main() -> None:
    response = create_demo_response("Token usage 为什么需要记录？")
    print(response.output_text)
    print({
        "input_tokens": response.usage.input_tokens,
        "output_tokens": response.usage.output_tokens,
        "total_tokens": response.usage.total_tokens,
    })

if __name__ == "__main__":
    main()

os.environ["OPENAI_MODEL"]读取必须存在的环境变量，缺失时抛 KeyError，比悄悄选择未知模型更诚实；OpenAI()默认从环境读取 Key；input=messages传入角色化消息；response.output_text取得聚合文本；response.usage提供本次调用的 Token 统计。真实 Key 只放本地环境或未提交的 .env。

先写再求助

  2. 先运行，记录成功输出和 usage；不要把 Key 或完整私人输入放进截图/日志。
  3. 若报错，先复制“异常类型 + 状态码 + request id + 最小上下文”，再让 AI 分析。
  4. 修复后重跑，并记录“原错误—原因—改动—结果”。

6｜usage、API Error 与边界实验

正常档 1h（含验收）

usage是调用的资源记录，用于估算成本、发现意外长输入和比较版本；API error要按类型判断是修配置、修请求、等待重试还是检查网络。不要用一个空泛的 except Exception 把所有原因变成同一句“调用失败”。

from openai import (
    APIConnectionError,
    APIStatusError,
    AuthenticationError,
    RateLimitError,
)

try:
    response = create_demo_response("请解释 system message 的作用。")
except AuthenticationError as exc:
    print("认证失败：检查 Key，但不要打印 Key。", exc.request_id)
except RateLimitError as exc:
    print("触发限流：记录 request_id，稍后重试。", exc.request_id)
except APIConnectionError:
    print("连接失败：检查网络、代理与超时。")
except APIStatusError as exc:
    print("服务返回非 2xx：", exc.status_code, exc.request_id)
else:
    print(response.output_text)

故意错误实验

  1. 把 OPENAI_MODEL 临时设为明显不存在的值，运行一次并记录异常类型、状态码和 request id；随后恢复正确模型。
  2. 在不泄露 Key 的前提下，记录修复前后命令与结果。
  3. 若当前没有可用 Key，只能完成本地函数、mock 与测试，真实成功调用和服务端错误必须标为待验收，不能假装完成。
