一、Vector Database：不是“会理解文本”的数据库

2 小时
P0AI 主讲 + 主课程

Vector Database（向量数据库）在本周的职责是保存向量及其业务记录，并根据距离运算返回邻近记录。Embedding 模型负责把文本变成向量；数据库负责持久化、过滤、排序和返回数据。两者不要混成一个黑盒。

Chunk + metadata→Embedding→PostgreSQL / pgvector→Filter + Top-k

这周要保存的最小记录

{
  "chunk_id": "guide-003",
  "source": "guide.md",
  "content": "空文档应在清洗阶段拒绝……",
  "metadata": {"category": "pipeline", "language": "zh"},
  "embedding_model": "text-embedding-3-small",
  "embedding": [0.012, -0.034, ...]
}
  • chunk_id：稳定主键，支持重复运行与 Upsert。
  • content / source：查询命中后能还原上下文与来源。
  • metadata：结构化过滤条件，不塞入整段正文。
  • embedding_model：避免模型更换后把不兼容向量混在一起。
  • embedding：维度必须等于建表时声明的维度。

学习方法

讲解 35m：让 AI 区分 Embedding 服务、Retriever 与 Vector Store。主课程 25m：只读 All-in-RAG 的向量存储入门段落。动手 40m：为 W08 JSONL 补齐上面的字段。闭卷 20m：画出写入与查询两条数据流。

二、PostgreSQL + pgvector：定义可验证的存储 Schema

2.5 小时
P0官方文档主讲 + 实验主导

PostgreSQL负责关系数据、事务与查询；pgvector扩展增加 vector 类型和距离运算符。先在已安装 pgvector 的本地 PostgreSQL 中执行：

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS document_chunks (
    chunk_id text PRIMARY KEY,
    source text NOT NULL,
    content text NOT NULL,
    metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
    embedding_model text NOT NULL,
    embedding vector(1536) NOT NULL,
    updated_at timestamptz NOT NULL DEFAULT now()
);
不要盲抄 1536：它只是本教程所用示例模型的向量长度。先运行一次 Embedding，打印 len(vector)，再让表维度与实际模型配置一致；切换模型或维度时应重建该批向量。

错误示例 → 报错原因 → 正确做法

错误：维度不匹配

embedding vector(768)
-- 实际写入 1536 维

pgvector 会拒绝不同维度。先测实际长度，再建表。

错误：把 metadata 存成拼接字符串

metadata text  -- "category=pipeline,lang=zh"

难以稳定过滤。使用 jsonb，字段名保持一致。

-- 建表后自查
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'document_chunks'
ORDER BY ordinal_position;

必须动手

创建一张空表；插入 1 条手写测试记录；用 SELECT chunk_id, source, metadata FROM document_chunks; 读回。确认主键重复时会报错，再进入 Upsert。

三、Psycopg 3：参数绑定、事务与可重复 Upsert

3 小时
P0官方文档主讲 + 实验主导

Psycopg是 Python 的 PostgreSQL 驱动。不要用 f-string 拼 SQL 值；使用 %s 占位符和参数序列。连接上下文正常退出会提交，发生异常会回滚。

import os
import psycopg
from pgvector.psycopg import register_vector
from psycopg.types.json import Jsonb

UPSERT_SQL = """
INSERT INTO document_chunks (
    chunk_id, source, content, metadata, embedding_model, embedding
) VALUES (%s, %s, %s, %s, %s, %s)
ON CONFLICT (chunk_id) DO UPDATE SET
    source = EXCLUDED.source,
    content = EXCLUDED.content,
    metadata = EXCLUDED.metadata,
    embedding_model = EXCLUDED.embedding_model,
    embedding = EXCLUDED.embedding,
    updated_at = now()
"""

def save_chunks(rows: list[dict]) -> None:
    if not rows:
        raise ValueError("rows 不能为空")

    with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
        register_vector(conn)
        values = [
            (
                row["chunk_id"], row["source"], row["content"],
                Jsonb(row["metadata"]), row["embedding_model"],
                row["embedding"],
            )
            for row in rows
        ]
        with conn.cursor() as cur:
            cur.executemany(UPSERT_SQL, values)

常见错误

危险：拼接用户值

sql = f"SELECT * FROM document_chunks WHERE source = '{source}'"

引号、特殊字符会破坏 SQL，也会产生注入风险。值始终走参数绑定。

隐蔽：逐行提交

for row in rows:
    insert(row)
    conn.commit()

中途失败会留下半批数据。小批量用一个事务；异常时让上下文回滚。

为什么 Upsert：W08 Pipeline 重跑后，同一 chunk_id 更新而不是复制。重复执行两次后，行数应不变；修改一条 content 后，记录应更新。

练习顺序

环境变量连接 20m → 注册 vector 类型 20m → 写入 5 条 50m → 重复运行与更新实验 40m → 故意制造维度错误并观察回滚 30m → 整理函数与日志 20m。

四、Cosine Top-k：用 SQL 完成过滤后的邻近查询

3 小时
P0实验主导

pgvector 的 <=> 返回 cosine distance（余弦距离）：越小越近。为了展示直观分数，可用 1 - distance 得到 cosine similarity，但排序仍按距离升序。

from dataclasses import dataclass

@dataclass(frozen=True)
class SearchHit:
    chunk_id: str
    source: str
    content: str
    metadata: dict
    score: float

SEARCH_SQL = """
SELECT chunk_id, source, content, metadata,
       1 - (embedding <=> %s) AS score
FROM document_chunks
WHERE embedding_model = %s
ORDER BY embedding <=> %s
LIMIT %s
"""

def search(conn, query_vector, model: str, top_k: int = 3):
    if top_k < 1 or top_k > 20:
        raise ValueError("top_k 必须在 1 到 20 之间")
    register_vector(conn)
    with conn.cursor() as cur:
        cur.execute(
            SEARCH_SQL,
            (query_vector, model, query_vector, top_k),
        )
        return [SearchHit(*row) for row in cur.fetchall()]

Query → Vector Store 的完整边界

def retrieve(query: str, top_k: int = 3) -> list[SearchHit]:
    if not query.strip():
        raise ValueError("query 不能为空")
    query_vector = embed_texts([query])[0]  # 沿用 W09 适配层
    with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
        return search(conn, query_vector, "text-embedding-3-small", top_k)
  • Query 与 Chunk 必须用同一 Embedding 模型与维度。
  • ORDER BY ... <=> ... ASC 才是最近优先；写成降序会返回最不相似记录。
  • LIMIT 控制返回数量，不是相似度阈值。
  • Top-k 总会返回现有记录；库外问题仍需记录为检索边界。

必须动手

复用 W09 的 6 个固定查询，分别运行内存版与数据库版；对比 Top-3 的 chunk_id。若顺序不同，先核对模型、向量数据、距离方向和过滤条件，不要立刻加新框架。

五、Metadata filter + 基础 Index / EXPLAIN

3 小时
P0 过滤P1 索引与计划

Metadata filter（元数据过滤）先限定候选记录，再按向量距离排序。例如只检索中文 pipeline 文档：

SELECT chunk_id, source, content, metadata,
       1 - (embedding <=> %(query)s) AS score
FROM document_chunks
WHERE embedding_model = %(model)s
  AND metadata->>'category' = %(category)s
  AND metadata->>'language' = %(language)s
ORDER BY embedding <=> %(query)s
LIMIT %(top_k)s;

使用固定、可解释的 metadata 字段。不要把过滤器作为 SQL 片段从外部直接拼进查询；允许的字段应由程序白名单映射。

P1：只观察，不做过度优化

CREATE INDEX IF NOT EXISTS document_chunks_category_idx
ON document_chunks ((metadata->>'category'));

CREATE INDEX IF NOT EXISTS document_chunks_embedding_hnsw_idx
ON document_chunks USING hnsw (embedding vector_cosine_ops);

EXPLAIN
SELECT chunk_id
FROM document_chunks
WHERE metadata->>'category' = 'pipeline'
ORDER BY embedding <=> '[0.01, 0.02, ...]'
LIMIT 3;
两条边界：EXPLAIN 只展示计划；EXPLAIN (ANALYZE, BUFFERS) 会实际执行查询，只对安全 SELECT 使用。小表很可能选择顺序扫描，这不代表索引“坏了”。HNSW 是近似索引，带过滤时还要关注候选不足；本周只记录现象，不调大量参数。
实验过滤条件Top-3计划观察结论
A无记录 IDSeq / Index Scan基线
Bcategory=pipeline记录 ID过滤行数结果是否更聚焦
C不存在的 category空—程序如何返回
