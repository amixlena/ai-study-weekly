3. 每个任务的详细解读

1. Token / Tokenizer / 自回归生成

P0L2

理解与用途：分词器（Tokenizer）把文本转成 Token 序列。自回归生成每一步根据当前上下文预测下一个 Token，再将它加入上下文继续生成，因此输入长度、输出长度和生成耗时相互关联。

具体怎么做：在 Token 实验记录中比较中文、英文、代码三种输入；记录使用的 tokenizer 或模型及计数来源。再比较短输出与长输出，并画出下一 Token 概率、采样、追加、继续生成的循环。

学到这里即可：解释字符数不等于 Token 数，闭卷画出完整生成链；不同 tokenizer 的计数不混作同一模型的准确计费依据。

这项任务怎么学

学习参考资料：李宏毅：Token、Tokenizer 与生成机制相关选段；Happy-LLM：仅补 Tokenizer 难点；实际模型的 tokenizer / 用量文档。Models（使用 OpenAI 时） 用于核对所选模型入口；本页固定资料与选段说明。

学习方法：AI 主讲 + 实验：AI 先串起生成链，你复述；立即比较中文、英文和代码的计数，再用实际模型文档校准计数来源。

建议时长：2h。生成链讲解 / 资料 0.75h + Token 实验与复述 1.25h。

学习建议：先理解 Token 与字符数的区别；不学习 tokenizer 训练。画图和小实验都包含在这 2h 内。

2. Embedding / Attention / Transformer / Decoder-only

P0L1–L2

理解与用途：嵌入表示（Embedding）把 Token 变成向量；注意力机制（Attention）让当前位置从可见上下文聚合信息。Q 可理解为查询，K 为匹配线索，V 为被汇集的信息。Transformer Block 组合注意力等处理，Decoder-only 生成时使用因果约束。

具体怎么做：围绕一句包含指代的短句解释“它”需要参考哪些词；画出 Token、Embedding、Block、输出概率的关系，用纸面小例子说明不同关注权重会改变聚合信息。不要实现训练或完整 Transformer。

学到这里即可：用 3 分钟解释 Q/K/V、上下文交互和因果约束；能把组件放回生成链，而非只背缩写。

这项任务怎么学

学习参考资料：李宏毅：Embedding、Self-attention、Transformer、Decoder-only 相关选段；Happy-LLM 仅补不理解的概念。查看本页课程选段及视频入口。

学习方法：原课程主讲 + AI 重讲：先看必要图示，暂停后自己画关系；让 AI 只解释 Q/K/V 和因果约束的难点，再用指代例子复述。

建议时长：3h。原课程 / AI 重讲 1.75h + 纸面实验、画图与复述 1.25h。

学习建议：以 L1–L2 为止：会解释组件关系和做最小示例即可，不延伸到完整公式推导或训练。

3. LLM API / Messages / Context

P0L2

理解与用途：API 将消息和参数发送给模型并返回输出。system/user/assistant 表达指令、用户输入与对话历史的角色；上下文窗口（Context Window）限制模型本次可处理的信息范围。

具体怎么做：在 llm_api_demo 中完成一次最小调用。固定问题，只改变角色指令；再加入一段 assistant 历史比较结果。记录请求、响应正文与 usage 的位置，并用环境变量读取密钥。

学到这里即可：从空白脚本重写最小调用，能修改消息并解释模型实际收到什么；按实际供应商核对字段。

这项任务怎么学

学习参考资料：实际供应商的消息、请求与响应文档；Responses API Reference（使用 OpenAI 时）；Models（使用 OpenAI 时）。LLM Cookbook 只查 Messages / API 部分。

学习方法：官方文档主讲 + 实验：AI 先解释请求响应，阅读实际使用接口的最小示例，跑通后自己修改角色消息并观察 usage。

建议时长：3h。官方文档与请求解释 1h + 最小调用 / Messages 实验 2h。

学习建议：只选一个实际使用的模型和接口；这里的 OpenAI 链接是条件入口，其他供应商用其对应文档，不混抄字段。

4. Temperature / Top-k / Top-p / Max Tokens

P0L2

理解与用途：Temperature 调整采样分布，Top-k 限制候选数量，Top-p 按累计概率筛选候选，输出上限限制生成长度。参数影响输出行为，不是“越大越好”或“越小越准确”。

具体怎么做：在参数实验记录中固定模型和 Prompt，每次只改一个受支持参数，重复运行并记录文本差异、Token 与耗时。Top-k 或其他参数不受当前模型支持时，记录限制并用纸面概率例子解释，不为了实验更换整套主线。

学到这里即可：能用对照记录解释观察，不把一次输出当普遍结论；输出上限字段及可用参数以当前模型文档为准。

这项任务怎么学

学习参考资料：实际模型的采样参数与输出上限说明；Responses API Reference（使用 OpenAI 时） 和 Models（使用 OpenAI 时） 用于核对所选 OpenAI 模型支持范围；Checklist 的 API 参数条目用于检查概念覆盖。

学习方法：实验主导：固定模型和 Prompt，每次只改一个受支持参数，重复运行并记录；不支持的参数用纸面概率例子解释。

建议时长：2.5h。参数文档 0.5h + 单变量实验与记录 2h。

学习建议：实验记录集中一张表；不用一次改变多个参数，也不把低 Temperature 当成准确性保证。

5. Streaming / Usage / Cost / Latency / Error

P0L2（执行建议）

理解与用途：流式输出（Streaming）让响应逐段到达；一个事件不一定对应一个 Token。Usage 记录用量，Latency 反映延迟，Cost 根据供应商计费规则估算。错误需要先定位请求、参数还是访问限制。

具体怎么做：比较一次普通与流式调用，记录首段文本等待时间和总耗时；记录输入/输出用量，注明计费来源。故意发送一个无效参数，保留脱敏错误信息，修正后重跑。

学到这里即可：有正常流式记录和一条已理解的错误；能区分首段延迟与总耗时。本组 L2 是对计划实践要求的操作化说明。

这项任务怎么学

学习参考资料：实际供应商的 Streaming、Usage、Error 文档与计费页；Responses API Reference（使用 OpenAI 时） 可查对应流式请求和事件定义（使用 OpenAI 时）。

学习方法：官方文档 + 实验：比较普通与流式输出，记录首段和总耗时；主动造一次参数错误，读错误并修正，再核对用量字段。

建议时长：2h。官方文档 / 错误字段 0.5h + 普通与流式对照、失败修复 1.5h。

学习建议：只制造可控的无效参数错误，不反复冲击限流；计费价格临用时查实际供应商，记录来源，不凭记忆填价格。

6. timeout / retry / Seed / Prompt 影响

P1L1；有余力做 L2（建议）

理解与用途：超时限制等待时间，重试用于适合再次尝试的临时失败；Seed 与确定性取决于模型支持，不能直接承诺完全复现。

具体怎么做：P0 验收后，阅读实际供应商对应说明，写出哪些错误可重试、哪些需先修正请求。对支持的 Seed 或简单 Prompt 做一次补充对比，时间不够取消本次扩展。

学到这里即可：能解释用途和边界；本周不实现复杂重试、并发或生产可靠性系统。

这项任务怎么学

学习参考资料：实际供应商 SDK 的 timeout / retry、模型 Seed 支持说明；Models（使用 OpenAI 时） 与 Responses API Reference（使用 OpenAI 时） 作为所选 OpenAI 模型的核对入口。

学习方法：AI 解释 + 官方文档确认：先说清超时和临时失败区别，再写可重试 / 应修正请求的条件；有余力才追加一次实验。

建议时长：1h。概念与文档 0.5h + 可选对照 / 重试条件说明 0.5h。

学习建议：P1 只在 P0 通过后做；P0 超时则把这 1h 改作 Debug 缓冲。复杂重试与并发留到项目阶段。

知识之间的关系

文本→Token / Tokenizer→Embedding→Transformer / Attention→Next Token Probability→Sampling→新 Token

API 侧再把这条内部机制映射到：messages / context → model → parameters → streaming / usage / error。本周要建立的是两条线之间的联系，而不是孤立背术语。

W01-W03 Python / Git 启动→W04 LLM 最小底层→W05 Structured Output + Context + Agent 全景→W06 Tool Calling + Agent Loop

W04 不要求训练模型或实现 Transformer。它承担的是“建立应用工程所需模型直觉 + 学会观察模型 API 行为”的作用，后面 Structured Output、Tool Calling、RAG 和 Agent 都依赖这些基础概念。
