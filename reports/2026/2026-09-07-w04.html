P02.0h · 12.5%

任务 A｜Token / Tokenizer + 生成总流程

要解决的问题：模型为什么不是“直接读一句中文”，而是先处理 Token；又为什么生成是一小步一小步接下一个 Token。

  1. 先用中文理解 Token、Tokenizer、input token、output token、context window。
  2. 拿 3 组输入做 Token 对比：短中文、英文、代码 / 标点混合文本。
  3. 把完整生成过程画成一条链：文本 → Token → Embedding → Transformer → 概率 → Sampling → 新 Token。
  4. 闭卷回答：为什么 Token 数会影响成本、延迟和最大输入长度？

验收：能够不看资料解释“字符数 ≠ Token 数”，并把 Token 与 Context Window、Cost 连起来。

P03.0h · 18.8%

任务 B｜Embedding / Attention / Transformer / Decoder-only

本周深度：只到 L1-L2。目标是解释用途与数据流，不要求手推公式或自己实现 Transformer。

  1. Embedding：理解 Token ID 如何变成可计算的向量表示。
  2. Attention：重点解释“一个 Token 为什么需要参考上下文中的其他 Token”；Q/K/V 只需知道大致角色。
  3. Transformer Block：知道 Attention 是 Block 的核心组成之一，不需要展开训练细节。
  4. Decoder-only：理解 GPT 类模型为什么适合做 Next Token Prediction。
  5. 最后把 Attention 放回整个生成链，而不是孤立背概念。

验收：3 分钟解释 Attention，并明确说出本周“不要求从零实现 Transformer”。

P03.0h · 18.8%

任务 C｜LLM API / Messages / Context / Token Usage

目标：从“会聊天”变成“知道应用代码发了什么、模型收到了什么、返回了什么”。

  1. 跑通一个最小 LLM API 调用。
  2. 分别修改 system / user message，观察角色变化。
  3. 记录 request、response、usage、输入 / 输出 token。
  4. 逐步增加上下文，观察输入长度、延迟和回答变化。
  5. 不要把 API Key 写进代码仓库；使用环境变量或本地配置。

验收：能指出 Message、Context、Token Usage 在代码里分别在哪里；能独立修改 system message 并解释变化。

P02.5h · 15.6%

任务 D｜采样参数实验

核心方法：不要只背定义，使用同一个 Prompt 重复实验，把参数差异变成可观察结果。

  1. 固定 Prompt，比较较低与较高 Temperature。
  2. 理解 Top-p / Top-k 的作用边界；若当前模型不暴露某参数，则以概念理解和官方文档为准，不强行实验。
  3. 修改 Max Tokens / 最大输出长度，观察截断或输出长度变化。
  4. 记录：参数、输出差异、延迟、Token Usage。
版本提醒：不同模型支持的采样参数不同。以你实际调用模型的当前官方文档为准，不照搬旧教程参数。
P02.0h · 12.5%

任务 E｜Streaming / Cost / Latency / Error

  1. 跑一次普通返回，再跑一次 Streaming，描述用户体验差异。
  2. 记录一次请求的 latency 和 token usage；理解二者为什么是 AI 应用工程指标。
  3. 故意制造至少一个错误：非法参数、缺失 Key、错误模型名或其他安全可控的 API Error。
  4. 读 traceback / error response，而不是直接让 AI 替你修完。

验收：能解释 Streaming 不是“模型更快”，而是更早把部分结果展示给调用方；能说出至少一种 API 错误的处理思路。

P02.5h · 15.6%

任务 F｜Definition of Done：闭卷解释 + 修改 + 重写

  1. 关闭资料，重新画一次 LLM 生成流程图。
  2. 从空白 / 骨架重新写一次最小 API 调用核心部分。
  3. 自己改至少一个 Message 和两个参数，并预测结果后再运行。
  4. 把一次正常路径 + 一次错误路径记录到 Markdown。
  5. 最后回答“为什么 W04 对后面的 Structured Output / Agent / RAG 有用”。
