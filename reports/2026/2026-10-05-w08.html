一、Document Pipeline：先定义数据契约

2 小时
P0AI 主讲 + 实验主导

Document Pipeline（文档处理流水线）是把原始文件转换成统一 Document，再转换成 Chunk 的可重复过程。它位于 RAG 最前端：本周输出会在 W09 被 Embedding 和 Retriever 使用，在 W12 被固定测试集评估。

原始文件→读取→清洗→Document + metadata→Chunk→校验 / JSONL

最小目录：data/raw/ 保存公开或合成输入，src/document_pipeline.py 放可复用逻辑，tests/test_document_pipeline.py 放回归测试，artifacts/chunks.jsonl 放生成结果。原始输入不在处理中被覆盖。

from pydantic import BaseModel, Field

class Document(BaseModel):
    text: str = Field(min_length=1)
    source: str = Field(min_length=1)
    metadata: dict[str, str | int] = Field(default_factory=dict)

class Chunk(BaseModel):
    chunk_id: str
    text: str = Field(min_length=1)
    source: str
    start: int
    end: int
    metadata: dict[str, str | int] = Field(default_factory=dict)

先弄懂再写

text 是后续被检索的内容；source 回答“这段来自哪里”；metadata 保存标题、类型、时间等过滤或解释信息；start/end 让 Chunk 可以映射回原文。

停止点：能画出数据流，并说出每个字段为何存在；不要在这里设计完整数据库模型。

二、读取、保守清洗与 metadata

3.5 小时
P0官方文档主讲 + 实验

Document Loader（文档读取器）负责把不同文件变成统一字符串；Cleaning（清洗）只移除确定是噪声的内容；Metadata（元数据）保存来源和结构信息。清洗的原则是可解释、可回退，不要为了“干净”破坏标题和段落。

from pathlib import Path
import re

ALLOWED_SUFFIXES = {".txt", ".md"}

def normalize_text(text: str) -> str:
    text = text.replace("\r\n", "\n").replace("\r", "\n")
    lines = [re.sub(r"[ \t]+", " ", line).strip() for line in text.split("\n")]
    cleaned = "\n".join(lines)
    cleaned = re.sub(r"\n{3,}", "\n\n", cleaned).strip()
    if not cleaned:
        raise ValueError("document is empty after cleaning")
    return cleaned

def load_documents(root: Path) -> list[Document]:
    paths = sorted(p for p in root.rglob("*") if p.suffix.lower() in ALLOWED_SUFFIXES)
    documents: list[Document] = []
    for path in paths:
        raw = path.read_text(encoding="utf-8")
        documents.append(Document(
            text=normalize_text(raw),
            source=path.as_posix(),
            metadata={"suffix": path.suffix.lower(), "filename": path.name},
        ))
    return documents

常见错误：不指定编码

# 错误：依赖操作系统默认编码
raw = path.read_text()

同一文件可能在不同机器产生 UnicodeDecodeError 或不同结果。正确做法是显式使用 encoding="utf-8"；真实数据若不是 UTF-8，应记录并转换，而不是用 errors="ignore" 静默丢字符。

常见错误：把所有空白压成一行

# 错误：标题、列表和段落边界全部消失
cleaned = " ".join(raw.split())

正确做法是只合并行内连续空格，并把三个以上换行压成两个，保留段落作为后续切块边界。

练习骨架

补充 .md 与 .txt 各两份合成文本，包含 Windows 换行、多余空格、空文件和中文。你先实现 normalize_text；卡住时只让 AI 给一个 Hint，不直接索取完整答案。

边界测试：空目录、空文件、仅空白文件、UTF-8 中文、重复文件名位于不同目录。

三、Chunk size 与 overlap：实现固定窗口

3.5 小时
P0实验主导

Chunk（文本块）是检索的最小单元；chunk size（块大小）决定每块携带多少上下文；overlap（重叠）让跨边界的信息在相邻块重复出现。块太小会丢上下文并制造大量碎片，块太大会混入无关内容并增加后续 Token 成本；overlap 太大则重复存储、重复召回。

from hashlib import sha256

def chunk_fixed(document: Document, chunk_size: int = 500, overlap: int = 80) -> list[Chunk]:
    if chunk_size <= 0:
        raise ValueError("chunk_size must be positive")
    if overlap < 0 or overlap >= chunk_size:
        raise ValueError("overlap must satisfy 0 <= overlap < chunk_size")

    chunks: list[Chunk] = []
    start = 0
    while start < len(document.text):
        end = min(start + chunk_size, len(document.text))
        piece = document.text[start:end].strip()
        if piece:
            raw_id = f"{document.source}|{start}|{end}|{piece}"
            chunks.append(Chunk(
                chunk_id=sha256(raw_id.encode("utf-8")).hexdigest()[:12],
                text=piece, source=document.source, start=start, end=end,
                metadata={**document.metadata, "strategy": "fixed"},
            ))
        if end == len(document.text):
            break
        start = end - overlap
    return chunks

危险错误：overlap 大于或等于 chunk size

# 错误参数：start 无法向前推进，可能形成死循环
chunk_fixed(document, chunk_size=200, overlap=200)

因此必须在进入循环前校验参数。不要等程序卡死后才处理。

对照实验

固定同一篇 1500–3000 字文本，分别运行 (300, 0)、(300, 60)、(600, 80)。记录块数、最短/最长块、重复字符比例，并人工检查两个跨段落问题是否能在单块中回答。

停止点：能解释参数变化，不追求“万能最佳值”。W12 会用固定评测集再比较。

四、段落优先切块：第二种策略

2.5 小时
P0用户实现 + AI 检查

固定窗口简单、稳定，但会在任意字符处切断语义。第二种策略先按空行获得段落，再把多个短段落装入目标大小；只有单个段落过长时才回退到固定窗口。这样能保留标题、列表和自然段边界。

def chunk_by_paragraph(document: Document, target_size: int = 500) -> list[str]:
    paragraphs = [p.strip() for p in document.text.split("\n\n") if p.strip()]
    result: list[str] = []
    current: list[str] = []
    current_len = 0

    for paragraph in paragraphs:
        extra = len(paragraph) + (2 if current else 0)
        if current and current_len + extra > target_size:
            result.append("\n\n".join(current))
            current, current_len = [], 0
        current.append(paragraph)
        current_len += len(paragraph) + (2 if len(current) > 1 else 0)

    if current:
        result.append("\n\n".join(current))
    return result
本例故意保留一个待处理边界：单段长度大于 target_size 时，上面代码仍会产生超长块。你的练习是检测这个条件，并调用固定窗口函数拆分该段；不要直接复制框架 splitter 掩盖逻辑。

比较维度

对同一文档比较固定窗口与段落优先：块数、长度分布、超长块数量、标题/列表是否完整、相邻块重复量。写下“这个样本更适合哪种策略以及为什么”，不能只写“效果更好”。

五、数据校验、稳定输出与可重复测试

2 小时
P0官方文档 + Debug

Reproducibility（可重复性）意味着相同输入和参数得到相同顺序、chunk_id 与内容。至少控制：文件排序、显式编码、确定性清洗、固定参数、稳定 ID、明确失败。

import json
from pathlib import Path

def save_jsonl(chunks: list[Chunk], output: Path) -> None:
    output.parent.mkdir(parents=True, exist_ok=True)
    lines = [json.dumps(c.model_dump(), ensure_ascii=False, sort_keys=True) for c in chunks]
    output.write_text("\n".join(lines) + "\n", encoding="utf-8")

测试不是只看“能运行”

def test_chunk_fixed_is_stable():
    doc = Document(text="甲" * 900, source="sample.txt")
    first = chunk_fixed(doc, chunk_size=300, overlap=60)
    second = chunk_fixed(doc, chunk_size=300, overlap=60)
    assert [c.model_dump() for c in first] == [c.model_dump() for c in second]
    assert all(c.text for c in first)
    assert all(0 <= c.start < c.end <= len(doc.text) for c in first)

def test_rejects_invalid_overlap():
    doc = Document(text="有效文本", source="sample.txt")
    try:
        chunk_fixed(doc, chunk_size=100, overlap=100)
        assert False, "expected ValueError"
    except ValueError as exc:
        assert "overlap" in str(exc)

输入路径必须 sorted；否则文件系统返回顺序不保证稳定。JSONL 使用 ensure_ascii=False 便于检查中文，sort_keys=True 便于回归比较。

必须验证

重复运行两次后比较输出文件哈希；删除一个输入、加入空文件、修改 chunk_size，再确认失败或变化符合预期。不要使用宽泛的 except Exception: pass 把坏数据吞掉。
