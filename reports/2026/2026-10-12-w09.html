一、Embedding：把语义映射成可比较的向量

3 小时
P0AI 主讲 + 主课程

Embedding（嵌入向量）是模型把文本映射成一列浮点数的结果。语义相近的文本通常在向量空间中更接近。Retriever 不直接“读懂”全文，它先把 Query 和 Chunk 放进同一个向量空间，再用相似度排序。

Chunk 文本→Embedding 模型→Chunk 向量↘相似度排序
Query 文本→同一模型→Query 向量↗

四条必须守住的契约

  • 同一模型：Chunk 和 Query 必须来自同一 Embedding 模型与配置。
  • 同一维度：长度不同的向量不可直接点积；切换模型后要重建全部 Chunk 向量。
  • 原文可追踪：向量必须和 chunk_id、文本、source 绑定，不能只保存一串数字。
  • 空文本前置拒绝：清洗后为空的 Chunk 不应进入 API。
from dataclasses import dataclass

@dataclass(frozen=True)
class Chunk:
    chunk_id: str
    text: str
    source: str

@dataclass(frozen=True)
class EmbeddedChunk:
    chunk: Chunk
    vector: list[float]

def validate_chunks(chunks: list[Chunk]) -> None:
    if not chunks:
        raise ValueError("chunks 不能为空")
    ids = [item.chunk_id for item in chunks]
    if len(ids) != len(set(ids)):
        raise ValueError("chunk_id 必须唯一")
    if any(not item.text.strip() for item in chunks):
        raise ValueError("Chunk 文本不能为空")

怎么学

讲解 45m：让 AI 用“地图坐标”类比解释向量，但随后回到数据契约。主课程 35m：只读 All-in-RAG「向量嵌入」中定义与检索相关段落。动手 70m：写 dataclass、校验与 5 个合成 Chunk。闭卷 30m：画出两条向量路径并解释为什么不能混模型。

二、调用 Embeddings API：批量输入并验证映射

2.5 小时
P0官方文档主讲 + 实验主导

以当前 OpenAI Python SDK 为最小示例。OpenAI() 从环境读取凭据；不要把密钥写进源码或公开仓库。一次传入多个文本便于减少请求次数，但返回后仍要检查数量、index 与维度。

from openai import OpenAI

client = OpenAI()

def embed_texts(
    texts: list[str],
    model: str = "text-embedding-3-small",
) -> list[list[float]]:
    cleaned = [text.strip() for text in texts]
    if not cleaned or any(not text for text in cleaned):
        raise ValueError("texts 必须是非空字符串列表")

    response = client.embeddings.create(model=model, input=cleaned)
    ordered = sorted(response.data, key=lambda item: item.index)
    vectors = [item.embedding for item in ordered]

    if len(vectors) != len(cleaned):
        raise RuntimeError("返回向量数量与输入不一致")
    dimensions = {len(vector) for vector in vectors}
    if len(dimensions) != 1:
        raise RuntimeError("同一批向量维度不一致")
    return vectors

常见错误 → 原因 → 正确做法

错误：循环逐条请求

vectors = [embed_texts([x])[0] for x in texts]

能跑但请求多、慢且更容易遇到中途失败。先用小批量列表调用；超长输入或限流再做分批。

错误：相信返回顺序而不验证

vectors = [item.embedding for item in response.data]

显式按 index 排序并校验数量，避免 Chunk 与向量错配。

版本边界：本页只固定调用形状，不把未确认的超时、重试、维度裁剪参数硬塞入请求。若使用其他供应商，替换 embed_texts 适配层，并以该供应商官方文档为准。

练习

先对 5 个 Chunk 批量生成向量，打印“输入数、返回数、维度、首个 chunk_id”，不要打印整条向量。故意加入空字符串，确认在发请求前失败；再删掉空串重跑。

三、Cosine similarity：比较方向，不被长度主导

2.5 小时
P0AI 主讲 + 手写实验

Cosine similarity（余弦相似度）是两个非零向量点积除以各自 L2 范数的乘积。它关注向量方向而不是绝对长度。W09 要会写、会测、会解释；不要求推导高等数学。

import numpy as np

def cosine_similarity(a: list[float], b: list[float]) -> float:
    left = np.asarray(a, dtype=float)
    right = np.asarray(b, dtype=float)
    if left.ndim != 1 or right.ndim != 1:
        raise ValueError("只接受一维向量")
    if left.shape != right.shape:
        raise ValueError(f"维度不一致: {left.shape} vs {right.shape}")
    denominator = np.linalg.norm(left) * np.linalg.norm(right)
    if denominator == 0:
        raise ValueError("零向量没有可用的 cosine similarity")
    score = float(np.dot(left, right) / denominator)
    return max(-1.0, min(1.0, score))

最小手算 / 代码实验

assert cosine_similarity([1, 0], [1, 0]) == 1.0
assert cosine_similarity([1, 0], [0, 1]) == 0.0

# 应抛错：维度不一致、零向量
# cosine_similarity([1, 0], [1, 0, 0])
# cosine_similarity([0, 0], [1, 0])

易错点：把 cosine distance 当 similarity；漏除范数；比较不同模型的向量；把相似度高直接等同于答案正确。Retriever 的分数只是排序信号，必须由固定 query / expected chunk 验证。

学习节奏

AI 解释公式 25m → NumPy 官方 dot/norm 20m → 手写函数 40m → 4 组边界测试 35m → 用真实 Embedding 比较三句语义 30m。

四、Baseline Retriever：Query → 排序 → Top-k

3.5 小时
P0实验主导

Retriever（检索器）接收查询并返回最相关的 Chunk。Baseline 用线性扫描即可：数据量小、流程透明、方便 Debug。W10 再把相同接口接到持久化向量存储。

from dataclasses import dataclass

@dataclass(frozen=True)
class SearchHit:
    chunk_id: str
    text: str
    source: str
    score: float

def retrieve(
    query: str,
    items: list[EmbeddedChunk],
    top_k: int = 3,
) -> list[SearchHit]:
    if not query.strip():
        raise ValueError("query 不能为空")
    if not items:
        raise ValueError("索引不能为空")
    if top_k < 1:
        raise ValueError("top_k 必须大于 0")

    query_vector = embed_texts([query])[0]
    hits = [
        SearchHit(
            chunk_id=item.chunk.chunk_id,
            text=item.chunk.text,
            source=item.chunk.source,
            score=cosine_similarity(query_vector, item.vector),
        )
        for item in items
    ]
    hits.sort(key=lambda hit: (-hit.score, hit.chunk_id))
    return hits[: min(top_k, len(hits))]

使用 (-score, chunk_id) 作为排序键，是为了相同分数时结果仍稳定。top_k 大于文档数时返回全部结果，而不是产生下标错误。

先建索引，再多次查询

def build_index(chunks: list[Chunk]) -> list[EmbeddedChunk]:
    validate_chunks(chunks)
    vectors = embed_texts([chunk.text for chunk in chunks])
    return [
        EmbeddedChunk(chunk=chunk, vector=vector)
        for chunk, vector in zip(chunks, vectors, strict=True)
    ]

index = build_index(chunks)          # Chunk 只嵌入一次
results = retrieve("如何处理空文档？", index, top_k=3)
错误模式：每次查询都重算全部 Chunk 向量；只返回文本而丢失 metadata；排序方向写反；把 top_k 当相似度阈值；吞掉 API 错误后返回空列表。每种错误都应能在日志或测试中被发现。
